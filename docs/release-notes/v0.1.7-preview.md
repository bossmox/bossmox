BossMox 0.1.7 preview: updates and restarts run on the BossMox server, moves stay off the cluster heartbeat, and a new Settings app.

**Update** with Update now in BossMox, or as root on the Proxmox node that holds the BossMox VM:

```sh
bash -c "$(curl -fsSL https://github.com/bossmox/bossmox/releases/latest/download/update-bossmox.sh)"
```

**New**

- **Settings app, with Recommended settings.** Four switches for Proxmox's own settings, each with what it does and whether BossMox recommends it:
  - **VM moves use their own network:** sets Proxmox's Migration network.
  - **Limit how fast moves run:** a move speed limit, 25 to 250 MB/s.
  - **HA moves its guests before a node shuts down:** Proxmox's HA shutdown policy, set to Migrate.
  - **Running guests start again after a node restart.**

  Every switch asks first and names the change.
- **Moves and the cluster heartbeat.** When live moves run on the only network the nodes use to check on each other, a few big moves can make the nodes lose touch, and HA then restarts a node. Health check now warns when that's the case and names the network to use instead. Until moves have their own network, BossMox moves one VM at a time (three otherwise). On a new cluster, setup asks which network moves should use.

**Changed**

- **Update all nodes and Restart keep going with the browser closed.** The run lives on the BossMox server, so signing in from anywhere picks it up where it is, and Stop works from any browser.
- **Safer runs.**
  - At each node's turn, BossMox re-reads what's running there. A guest that arrived during the run is moved off first, so it doesn't go down with the restart.
  - A VM that didn't move stops the run before that node is updated.
  - Stopping a run starts again anything it had shut down.
  - Bringing guests home waits for a restarted node to settle.
