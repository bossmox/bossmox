BossMox 0.1.3 preview: guests only move where they fit, and BossMox remembers where they live.

**Update** with Update now in BossMox (on 0.1.2), or as root on the Proxmox node that holds the BossMox VM:

```sh
bash -c "$(curl -fsSL https://github.com/bossmox/bossmox/releases/latest/download/update-bossmox.sh)"
```

**New**

- **Moves that fit.** Before restarting a node, or during Update all nodes, BossMox plans where each running guest goes from fresh numbers: enough free memory (counting each guest at its full set memory), processor room, every storage the guest uses present on the target, room to copy any disks on a node's own storage, never to an older Proxmox, and a VM set to the host's processor only to the same processor. The biggest guests go first, each to the node with the most room left, so the load spreads. If even one guest has nowhere to go, nothing moves, and BossMox names the guest, the node and the number that ruled it out.
- **Keep free on each node.** One setting, 10% by default, from 5 to 30%, for memory, storage and processor. Change it right in the Restart and Update all nodes windows; the plan redraws.
- **BossMox remembers where guests live.** The record is on the BossMox server, not in your browser, so any person and any browser can see what's away and use Move everything back.
- **The moves run on the server,** one at a time, each checked again for room just before it starts. Closing the page no longer strands a half-done move, and Stop halts after the guest that's moving.
- **Coming home.** After a restart, guests go home if they fit. One that doesn't stays where it is, running, and Update all nodes carries on. Move everything back tries again later.
- **Update all nodes checks every node first,** and won't start if any of them can't be emptied.

**Changed**

- A list of moved guests kept in the browser by 0.1.2 isn't carried over. If guests are still away from a restart done with 0.1.2, move them back by hand.

Tested on two nested test clusters, Proxmox 9.2 and 8.4, including an HA-managed guest and shared LVM-over-iSCSI storage. Details: docs/adr/0025-moves-that-fit.md.
