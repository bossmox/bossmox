BossMox 0.2.1 preview: email alerts, and updates that can't turn into a major upgrade by accident.

**Update** with Update now in BossMox, or as root on the Proxmox node that holds the BossMox VM:

```sh
bash -c "$(curl -fsSL https://github.com/bossmox/bossmox/releases/latest/download/update-bossmox.sh)"
```

**After updating, your browser warns about BossMox's certificate once more.** BossMox now has its own small certificate authority (see below), so its certificate is new. Accept it once as before. Or import BossMox's certificate authority into your browser or computer to stop the warning for good: it's at `/etc/bossmox/ca.crt` on the BossMox VM, and it can only vouch for BossMox's own address.

Each piece below was tested on a real test cluster, and has a written decision record in [docs/adr](https://github.com/bossmox/bossmox/tree/main/docs/adr).

**New: email alerts through Outlook** ([#34](https://github.com/bossmox/bossmox/issues/34), ADR 0040)

Settings → Alerts → Email (Outlook). Sign in with an Outlook.com, Hotmail or Microsoft 365 account: BossMox shows a short code, and you enter it at Microsoft's sign-in page on any device. Proxmox's alerts then come to the addresses you choose, from that account.
- BossMox can send mail as the account and can't read it. Its sign-in is kept encrypted, with the key in a separate file only BossMox can read. Turn off deletes it.
- **These go through BossMox**, so while BossMox is down they don't arrive. For alerts that do, pick ntfy, Discord, Slack, Teams or Gotify instead. BossMox sets up one destination at a time.
- Setting it up gives each node BossMox's certificate authority, so Proxmox reaches BossMox over HTTPS, never plain text. That authority can vouch for BossMox's own address and nothing else. Setting it up needs root@pam. A node added later shows in Health check until you save the alert settings again.
- **Microsoft 365 work accounts** need their admin to approve BossMox once, because the app isn't publisher-verified yet. Personal accounts don't.
- No SMTP: plain mail servers and app passwords are too unreliable to depend on. Gmail may follow once Google has reviewed a BossMox app.
- Tested end to end with a personal Hotmail account: Proxmox's test alert arrived.

**New: updates never cross into a new major version** ([#94](https://github.com/bossmox/bossmox/issues/94), ADR 0039)

If a node's Debian or Proxmox update sources point at a different release than the one it runs (for example `trixie` on a Proxmox 8 node), a normal update would carry out the whole major upgrade, unattended. BossMox now refuses to update that node, both in Update all nodes and in a node's Install updates, and says why. It uses Proxmox's own check, so it keeps working for future versions. Other sources, such as Docker's, are ignored once they've been downloaded. Upgrading to the next major version from BossMox is planned for 0.3.0 ([#95](https://github.com/bossmox/bossmox/issues/95)).
- Tested by pointing a node's sources at `trixie`: the update was refused. With the sources put back, it ran.

**New: BossMox's own certificate authority** (ADR 0040)

It lasts 20 years and can only vouch for BossMox's own addresses and names. BossMox's website certificate comes from it, lasts 825 days, and is renewed automatically every day once fewer than 60 are left. Health check warns if renewing ever fails.
