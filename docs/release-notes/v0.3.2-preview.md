BossMox 0.3.2 preview: help where you need it, and every option in BossMox.

**Update** with Update now in BossMox, or as root on the Proxmox node that holds the BossMox VM:

```sh
bash -c "$(curl -fsSL https://github.com/bossmox/bossmox/releases/latest/download/update-bossmox.sh)"
```

Upgrading a real three-node cluster from Proxmox VE 8.4 to 9 with BossMox worked, but left too much guessing: a warning that read like turning off HA, one line for ten minutes while packages installed, a Stop button that gave no sign it was heard, a run that stopped for room with no way forward, and a paid update source that appeared on its own. This release explains, shows progress, and keeps you inside BossMox. ([#110](https://github.com/bossmox/bossmox/issues/110), [ADR 0044](https://github.com/bossmox/bossmox/blob/main/docs/adr/0044-help-and-every-option.md))

**Help**

- Every item in Get ready to upgrade has a **?** that opens a fuller explanation right under it: what it is, what happens if you leave it, what BossMox does and doesn't touch, whether it's safe with guests running, and Proxmox's own page on it.
- A **Help** app on the desktop holds all of them.
- Clearer short texts. The shared-storage warning now says it changes one setting on each old disk, creates no disks, and doesn't affect running VMs or HA. The Ceph and systemd-boot findings are explained in plain words instead of Proxmox's raw text.

**Every option**

- **Upgrade this node**, beside Upgrade all nodes, with the same checks, confirmed with the node's name.
- **Empty this node** on a node's page: every running guest moved to other nodes for maintenance, nothing restarted. Move everything back brings them home.
- **Use the free channel on every node** in one go, instead of one confirm per node.
- One-node installs get the update button in Nodes.
- HA's **Fix this** unlocks containers as well as VMs, after checking nothing is still using them.

**Runs that show what they're doing**

- An upgrade shows its six steps with check marks, and while installing how many packages are set up and how long since the node last reported.
- Moves show how far they are: "Moving to node2, 45%".
- A run of several nodes says which node it's on. After **Stop**, it says what will happen from the step it's on.
- When there isn't room to move a node's guests, **Start again with the nodes not done** lets you try with a lower Keep free for that run only, or shut down named guests.

**Upgrades keep the free channel**

- Proxmox VE 9 adds its paid update source, switched on. On a node using the free channel without a subscription, every check for updates then failed. Get ready to upgrade now says up front which nodes BossMox keeps on the free channel, and the upgrade turns off only the paid source it added.

**Fixes**

- A failed upgrade no longer starts guests on a node whose new packages had begun installing.
- An upgrade counts as started only once the node shows its own job.
- Accounts with limited Proxmox permissions see only the parts of a run they're allowed to see.

Designed security-first: the design had two outside reviews before any code, and the build had three before release.
