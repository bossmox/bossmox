BossMox 0.1.8 preview: three cluster health fixes you can make from Health check.

**Update** with Update now in BossMox, or as root on the Proxmox node that holds the BossMox VM:

```sh
bash -c "$(curl -fsSL https://github.com/bossmox/bossmox/releases/latest/download/update-bossmox.sh)"
```

**New**

- **Fix this for VM moves on the heartbeat's network.**
  - One screen shows the networks every node shares that the heartbeat doesn't use, and any storage on each.
  - When the network you pick also carries storage, it sets a 250 MB/s limit (about 2 Gbps), so moves don't crowd the disks.
  - It says exactly what changes before anything does.
  - With no second network, it lists the steps to add one and offers a speed limit until then.
- **HA shutdown policy.** When HA manages guests and Proxmox's default policy is set, Health check warns that a node restarted by hand stops those guests. Fix this switches the policy to Migrate, so HA moves them off first.
- **Leftover disks.** Health check lists disks detached from their guests but still taking up space, often left behind by an import from another hypervisor, with each guest's name and the disk's size. Review and remove lets you untick any you want to keep before deleting the rest.

**Changed**

- **Settings knows which networks carry storage,** and recommends a move speed limit when moves share a network with it.
- **Setup never offers one of the heartbeat's networks for moves,** even on a cluster whose heartbeat has two links.
