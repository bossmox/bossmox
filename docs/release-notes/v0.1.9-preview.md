BossMox 0.1.9 preview: the fixes from the November code review.

**Update** with Update now in BossMox, or as root on the Proxmox node that holds the BossMox VM:

```sh
bash -c "$(curl -fsSL https://github.com/bossmox/bossmox/releases/latest/download/update-bossmox.sh)"
```

In November, two AI models that didn't write BossMox reviewed the whole codebase independently ([#42](https://github.com/bossmox/bossmox/issues/42)). This release fixes what they found. It then went through a second review of its own before shipping.

**Security fixes**

These were in [SECURITY.md](https://github.com/bossmox/bossmox/blob/main/SECURITY.md)'s scope, so they're published now that this release carries the fixes. Each is a closed issue with the details.

- **Wipe disk and Set up storage could erase a disk handed directly to a VM** if that VM's settings failed to load, or if your account couldn't see the VM. BossMox now refuses to erase any disk or pool when it can't be sure nothing uses it, and says why.
- **Deleting an empty ZFS storage could also erase another storage kept inside the same pool.** It's refused now.
- **An ISO with a space in its name ("Windows 11.iso") wasn't seen as in use,** so it could be deleted while mounted.
- **Delete backup accepted a request naming something that isn't a backup.** It now only deletes what the storage lists as a backup.
- **During setup, entering the setup code again didn't sign out the person before,** so their root password stayed in memory. It's dropped now.
- **Run and move progress showed node and guest names to any signed-in account.** An account that can't see the whole cluster now sees only its own nodes and guests.

**Fixed: updates and restarts**

- **On a two-node cluster with HA guests, a run could restart the node left running.** A run now refuses when HA guests would be left on fewer than three votes. Health check counts a tie-breaker's vote only when it's connected.
- **Pressing Stop while a node was rebooting left the guests BossMox had shut down switched off.** They're started again now.
- **Updates can't be broken mid-install.** apt runs as its own job on the node, so it finishes even if BossMox loses the console, and two never run at once.
- **A guest that landed on a node during its update** is moved off before the restart.
- **BossMox installed in a container** recognises itself, and won't restart its own node.
- **Discs chosen for ejecting** only come out once every check has passed.
- **A move BossMox lost sight of but Proxmox finished** is recorded where it went, so Move everything back can bring it home.
- **Guests coming home to a busy, just-restarted node** are tried again instead of staying away, and a batch counts each other's processor load.
- **A run won't start on a sign-in about to expire,** so it can't be cut off partway.

**Fixed: setup, install and the app**

- **Setup:** one malformed request could stop the setup screen, and IPv6 node addresses broke setup.
- **Install and update:**
  - A failed install no longer leaves an empty VM behind.
  - Updating keeps your hand-edited settings and puts them back if the update is rolled back.
  - The container install can save its state.
- **VM Settings:** saving no longer undoes a change someone else made meanwhile.
- **The moves window** stops reopening over other windows.
- **Asking first:** Keep free asks before changing a cluster-wide setting.
- **Update all nodes:** stops if checking for updates failed.
- **Uploads:** an upload says it's ready only once Proxmox has saved it, and an expired sign-in goes straight to the sign-in screen.
- **Smaller fixes:**
  - A Proxmox fault isn't counted as a wrong password.
  - Slow changes aren't reported as failures.
  - An older VM's boot disk is protected.
  - Bind mounts and HA groups are respected when planning moves.

**Under the hood**

- **The server's code is split by area** (moves and runs, actions, routes) and tested against a fake Proxmox.
- **A linter runs on every change.**
- **35 tests have been added since the review,** each for a specific fix.
